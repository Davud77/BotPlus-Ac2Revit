# BotPlus Ac2Revit

Транслятор Archicad → JSON/IFC → Revit 2026: Python-экстрактор через Tapir и C#-надстройка с кнопками экспорта, продолжения и сборки. Геометрия, единицы, координаты и соответствие исходных GUID обрабатываются детерминированным кодом.

**Версия исходников: 0.45.0.** [Сборка и установка после клонирования](INSTALL.md). Репозиторий содержит код, тесты, контракты и необходимые RFA/RFT; большие модели и результаты локальных запусков исключены.

Порядок: ресурсы/штриховки → оси → колонны → стены/перекрытия → балки → проёмы/заполнения → дополнительные IFC-объекты → разделители → сопряжения → помещения → отчёты. Помещения проверяются с допуском 1 м². Тела сложных неподдержанных элементов могут оставаться DirectShape с явной пометкой.

Последняя работа: [повторный сбой Ипподрома, координаты и исправления](docs/IPPODROM-TRANSFER-2026-10-18.md). Физическая сборка Ипподрома сохранена локально; полный расчёт помещений не завершён. В v45 добавлены сохраняемые пакеты помещений; завершение этого нового режима на реальной модели пока не подтверждено.

## Быстрый запуск

1. Откройте PLN в Archicad 28 с Tapir 1.7.0. API должен отвечать на `127.0.0.1:19723`. Для стабильного снимка не редактируйте модель и не переключайте документы во время выгрузки.
2. Из папки `exporter` запустите:

```powershell
python -m ac2r.export --output ../artifacts/abakan-v1 --project-id 5e5a43ba-b71f-4cf1-9eb4-bcb98248b8fc --properties --gdl --ifc
```

Этот UUID идентифицирует данную модель и должен сохраняться при перемещении PLN. Для другого проекта задайте другой UUID. Экстрактор использует только стандартную библиотеку Python; `requests` и пакет `archicad` не нужны.

На данном компьютере Python доступен по пути:

```text
C:\Users\davud\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe
```

Вычисляемые встроенные свойства могут быть очень дорогими. По умолчанию `--properties` получает доступные пользовательские свойства с типизированными значениями через официальный API. Все 1 831 определения свойств исходной модели сохраняются. Для чтения также встроенных значений добавьте `--property-scope all`; это отдельный длительный режим, не утверждается, что он уже полностью выполнен на этом PLN. При необходимости уменьшите `--metadata-batch` и `--property-batch`. `--include-2d` добавляет подробности всех чертёжных элементов; полный список GUID сохраняется и без этого флага.

В полученной модели сохранены 509 888 записей состояния пользовательских свойств: 118 326 имеют `normal`, 346 902 — `userUndefined`, 44 660 — `notEvaluated`. Неопределённые/невычисленные значения не заменяются нулями или выдуманными данными. Manifest и snapshot сохраняются компактным JSON: GDL и полная исходная геометрия делают их большими. `artifacts/sample/manifest.json` — небольшая выборка для проверки загрузки и отдельных адаптеров; в неё не включены все ограждения выбранной зоны, поэтому она не является готовым тестом замкнутости помещений. Для проверки помещений нужна связная выборка. Дальнейший промышленный этап должен вынести тяжёлые данные в адресуемые по хешу sidecar-файлы и добавить потоковое чтение.

`--resume` повторно использует архивированные ответы. Применяйте его только к **неизменённой** модели; проверка имени проекта и этажей не обнаруживает все изменения элементов. После изменения PLN создавайте новую выходную папку. При таймауте геометрический `snapshot.json` и `manifest.json` остаются доступными; `export-report.json` сообщает о незавершённости метаданных.

3. Соберите пакет:

```powershell
powershell -ExecutionPolicy Bypass -File tools/package.ps1
```

Проект не использует NuGet-пакеты. Установленный .NET SDK 10 компилирует целевой `net8.0-windows`, соответствующий Revit 2026. Ссылки на Revit DLL не копируются в пакет. Альтернатива для сборки: `python tools/package.py`.

4. Скопируйте `dist/Revit2026/Ac2Revit.addin` в `%APPDATA%\Autodesk\Revit\Addins\2026`, оставляя DLL на указанном в манифесте пути. Перезапустите Revit. Установка вне рабочей папки автоматически не выполнялась.
5. Создайте тестовый проект Revit. Шаблон `ADSK_RU_ШаблонПроекта_АР_r2021_v2.2.1.rte` потребует обновления при открытии в Revit 2026. Сохраните обновлённую копию отдельно.
6. Вкладка **Надстройки → Archicad JSON → Проверить JSON**: выберите `manifest.json`. Результат — `revit-preview.json` рядом с манифестом. Затем **Импорт JSON** выполняет создание и пишет `revit-import-report.json`.

## Какие элементы собираются

| Категория | Реализованное поведение |
|---|---|
| Этажи | Собственные Level по `story:index`; отметка в метрах → внутренние единицы Revit |
| Стены | Basic Wall, прямые/дуговые линии, многослойность, материал слоёв, core/shell, опорная линия, ориентация, смещение от этажа |
| Перекрытия | Floor, наружный контур и отверстия, дуги, конструкция, пересчёт опорной плоскости в отметку верха |
| Окна/двери | Wall-hosted FamilyInstance после стены; требуется явное сопоставление и калибровка семейства |
| Зоны | Room или Space после ограждений; точка внутри исходного полигона; проверка площади. Без ограждений или при несовпадении площади элемент откатывается |
| Колонны/балки | Прямые ненаклонные элементы через откалиброванные семейства; размеры, отметки и поворот. Сегментированные элементы и отверстия балок блокируются |
| Объекты/светильники | Эквивалентные unhosted OneLevelBased-семейства; размеры, поворот, согласованное зеркалирование |
| Morph | Исходное гранёное тело → DirectShape; локальная матрица и отверстия граней; для закрытого тела проверяется объём |
| Крыши, Mesh-рельеф, лестницы, ограждения, сложные стены | Подробности исходных элементов сохраняются; адаптеры создания пока отсутствуют |

`ready` в манифесте означает, что данные нормализованы. Это **не** подтверждение успешного импорта: Revit дополнительно проверяет минимальную толщину, короткие рёбра, валидность контуров, наличие типов/семейств и замкнутость помещений.

Свойства и классификации импортированных элементов сохраняются в Extensible Storage вместе с исходным JSON. Автоматическое создание всех shared parameters, appearance/thermal assets и перенос всех настроек печати не реализованы. Поверхностные overrides и текстуры Morph сохраняются как исходные данные; общий Building Material назначается геометрии.

## Сопоставление семейств

Скопируйте `config/mapping.example.json` в `mapping.json` рядом с выбранным манифестом. Список библиотечных объектов и количества экземпляров находится в `mapping-inventory.json`.

Ключ: `Kind:libraryGuid`, для профилированных колонн — `Column:profileGuid`; для уникальных элементов можно использовать `Kind:sourceGuid`. У обычных колонн/балок без библиотечного/profile GUID требуется сопоставление по source GUID. Заполните точные имена **уже загруженного** семейства и типа.

`calibrated=true` ставится после проверки тестового экземпляра: габариты, начало координат семейства, опорная линия/плоскость, сторона открывания и зеркало. Плагин не подставляет произвольное семейство по сходному имени.

- Окна/двери: `widthParameter`, `heightParameter`; пустое имя использует встроенные параметры. Типоразмер не изменяется глобально: если размеры являются параметрами типа, выбранный тип должен уже иметь нужные размеры. `sillFromWallBase`, `handFlipXor`, `facingFlipXor` калибруют различия размещения; исходный `oSide` сохраняется, но его универсальный маппинг не предполагается.
- Колонны: явные `widthParameter` и `depthParameter`; высота задаётся ограничениями колонны. Семейство должно быть TwoLevelsBased, категория Structural Columns.
- Балки: явные `widthParameter`, `heightParameter`; CurveDrivenStructural, категория Structural Framing. `originOffset` учитывает разницу между опорной линией Archicad и осью Revit. Для TopCenter часто нужна коррекция по Z, но она должна быть проверена для каждого сопоставления.
- Для колонн/балок с `isFlipped=true` дополнительно требуется подтверждённое `symmetricSection=true`; асимметричный отражённый профиль пока блокируется.
- Объекты: `widthParameter`, `depthParameter`, `heightParameter`; `originOffset`, `rotationOffsetRadians`; `allowMirroring=true` только после проверки отражённого экземпляра.

## Повторный импорт и ошибки

Импорт не сопоставляет элементы по марке или имени. Ключ — `(projectId, sourceGuid)`. При повторе неизменённые элементы пропускаются. Изменившиеся данные или конфигурация помечаются `conflict`; существующая модель сохраняется. **Обновление и удаление существующих элементов пока не реализованы.** Это защита от дубликатов, а не законченная двусторонняя синхронизация.

Каждый элемент создаётся отдельной Transaction внутри TransactionGroup. Хост попадает в индекс только после успешного commit. В режиме `allowPartial=true` ошибки отдельных элементов попадают в отчёт, независимые элементы продолжают создаваться. `allowPartial=false` откатывает всю группу при первой блокирующей несовместимости. Предупреждения Revit фиксируются в отчёте до удаления из failure processing.

Нулевые неструктурные слои отображаются в Membrane без изменения общей толщины. Положительные слои ниже лимита `CompoundStructure.GetMinimumLayerThickness()` не утолщаются автоматически. Прямые стены поддерживают ненулевое смещение опорной линии с пересчётом геометрической оси через `GetOffsetForLocationLine`; дуги с ненулевым смещением, наклонные/полигональные стены и неопределённая геометрия блокируются.

Соединения выполняются после размещения стен и перед созданием помещений по связям Archicad, с проверкой нативных соседей Revit. Несовместимые узлы изолируются в отдельных транзакциях. Абсолютный допуск площади помещения задаёт `roomAreaToleranceSquareMeters` (по умолчанию 1 м²); нулевая площадь не принимается. Подробности и выборочные проверки — [WALL-BINDING-AND-JOINS.md](docs/WALL-BINDING-AND-JOINS.md).

## Проверки

Для разработки добавлен `RuntimeJobs`: при наличии `artifacts/runtime/job.json` загруженный add-in выполняет диагностический импорт в **новый** проект, сохраняет RVT и открывает его 3D-вид. Пути входа/выхода ограничены рабочей папкой; существующий RVT не перезаписывается. Сетевого сервера и исполнения произвольного кода нет. Без файла задания обработчик ничего не создаёт.

`python tools/prepare_runtime_cases.py` готовит небольшую выборку и полную геометрическую выборку. Тяжёлые исходные метаданные остаются в оригинальном манифесте, на который записана ссылка. `python tools/queue_runtime_job.py sample` или `geometry` ставит один тест в локальную очередь. Файлы `result-v2-*.json` содержат прогресс/результат; `import-v2-*.json` — ошибки каждого элемента. `python tools/summarize_runtime.py ПУТЬ_К_ОТЧЁТУ` создаёт сводки JSON и Markdown.
