# Повторный импорт и обработка ошибок

## Идентичность и повторы

Ключ элемента — `(projectId, sourceGuid)`. Марка, имя, положение и номер этажа не заменяют исходный GUID. Неизменённые уже импортированные элементы повторно не создаются. Хеши исходных данных и конфигурации защищают от незаметной подмены.

План полной сборки проверяет снимок JSON/IFC и преобразование координат. Другой снимок требует нового проекта Revit: обновление изменённых элементов и удаление по изменившемуся источнику пока не реализованы. Это защита от дубликатов и смешения сеансов, а не законченная двусторонняя синхронизация.

## Ошибки и сохранность результата

Элементы создаются в транзакциях; в индекс хостов попадают только успешно зафиксированные элементы. В режиме `allowPartial=true` несовместимость отражается в отчёте, независимые элементы продолжают обрабатываться. `allowPartial=false` откатывает текущую группу при блокирующей ошибке. Сохранённые предыдущие этапы рассматриваются отдельно от текущей группы.

Предупреждения Revit записываются до обработки failure processing. Ошибки содержат этап, исходный ключ и причину. Статус завершения задания оценивается вместе с поэлементными результатами и покрытием GUID.

Резервные стены и их поясняющие подписи используют тот же обработчик: предупреждения о повторяющихся марках сохраняются в отчёте и не требуют подтверждения в модальном окне. Ошибки Revit откатывают соответствующую транзакцию; исходные марки автоматически не перенумеровываются.

| Результат | Значение |
|---|---|
| `created` / `unchanged` | Элемент создан / существующее представление сохранено |
| `conflict` | Источник или настройки изменились, требуется явная стратегия обновления |
| `blocked` / `unsupported` / `failed` | Адаптер не создал подтверждённый результат; причина в сообщении |
| `retained` / `incomplete` | Сохранён геометрический вариант или есть ограничение функциональности |
| `ready` во входном JSON | Данные подготовлены для адаптера; создание в Revit ещё не подтверждено |

## Геометрия и ограничения

Положительные слои ниже `CompoundStructure.GetMinimumLayerThickness()` автоматически не утолщаются. Геометрическая ось стены рассчитывается из опорной линии, сердцевины, ориентации и смещения, а не только из значения `WALL_KEY_REF_PARAM`.

Верхняя отметка перекрытия определяется через `API_SlabType.offsetFromTop`, если это поле присутствует. Оно позволяет обрабатывать `CoreTop/CoreBottom` у конструкций без слоёв Core. Для обычных конструкций значение дополнительно сверяется с толщинами и положением опорной плоскости; противоречия блокируются. [Описание поля Graphisoft](https://graphisoft.github.io/archicad-api-devkit/struct_a_p_i___slab_type.html).

Неподдержанные стены могут дополняться геометрическим вариантом с комментарием `НЕПОЛНОЦЕННАЯ СТЕНА`; точное тесселированное IFC-тело и аппроксимация различаются в отчёте. Заполнение с независимой IFC-геометрией может сохраниться при неподтверждённом вырезе, но получает отметку `НЕПОЛНОЦЕННОЕ ЗАПОЛНЕНИЕ`. Наличие двери не доказывает успешное вырезание её хоста.

Подготовительный статус `fillingOnly` разрешён только для однозначно идентифицированного физического заполнения с собственной геометрией. Обычно это `IfcDoor`/`IfcWindow`; нейтральный `IfcBuildingElementProxy` тоже допустим, если его явный IFC ID или точный GUID Tag связывает тело с исходной дверью/окном Archicad. Категория берётся из API, исходный IFC-класс и адаптация записываются в план и комментарий элемента. Иной смысловой класс, например `IfcDoor` для окна, не принимается. Заполнение сохраняется без создания выреза, когда связь IFC с проёмом отсутствует или не подтверждена. Хост не выбирается по близости. Неоднозначные идентификаторы и пустые проёмы без доказанной геометрии остаются заблокированными.

Стены с явно нулевой толщиной требуют отдельного представления. Сначала проверяется возможность сохранить IFC-тело. Если тело отсутствует, для поддержанной прямой простой стены сохраняется поверхность по номинальной оси и высоте API с пометкой `НЕПОЛНОЦЕННАЯ СТЕНА`; произвольная толщина и объём не добавляются. Это не подтверждение полного профиля после подрезок или проёмов. Для `zoneRel=Boundary` нативные разделители помещений создаются на исходных уровнях, расчётная плоскость которых пересекает высоту стены. Существующее IFC-тело получает такие разделители только при подтверждении его расположения в плоскости нулевой стены; противоречивое объёмное тело сохраняется без догадки о границе. Ошибки линий учитываются отдельно от наличия поверхности стены.

Если положительная толщина стены меньше геометрического допуска Revit и IFC-тело не принято, последний запасной вариант — помеченная номинальная срединная поверхность. Исходная толщина указывается в комментарии; объём и `Room Bounding` такого варианта не считаются перенесёнными.

Прямоугольная вертикальная колонна без принятого IFC-тела может быть дополнена нативной номинальной призмой по явным параметрам API. Такой элемент и его отдельный тип помечаются `НЕПОЛНОЦЕННАЯ КОЛОННА`. Проверяются номинальные габариты и объём, но не утверждается равенство фактической формы после подрезок/соединений. Сложные, наклонные, круглые, обёрнутые и неоднозначные сечения не подменяются прямоугольником.

Сопряжения опираются на исходные связи и проверку нативных соседей. Помещения создаются после физических элементов и соединений. Требуются положительная площадь и абсолютное отличие не более `roomAreaToleranceSquareMeters` (по умолчанию 1 м²); нулевая площадь не принимается.

Экспорт сохраняет исходные связи зон, балок, окон, дверей, крыш и оболочек в `raw.relations`; отчёт `relationCoverage` различает прочитанные записи, ошибки и пропуски. Эти связи дополняют геометрию контуров и служат основанием для разбора расхождений. Пока они не означают автоматическое исправление нативной границы помещения.

## Контрольные точки

Стадии сохраняют RVT и отчёты. Для длинных серий предусмотрено переоткрытие сохранённого документа, освобождающее накопленные кэши. Пакеты помещений сохраняют курсор и результаты в Extensible Storage; повторное продолжение использует подтверждённые контрольные точки.

Восстановление экспорта из архивов требует завершённого чтения и неизменного источника. Повреждённый существующий IFC не перезаписывается автоматически. Отсутствие элемента в неполном экспорте не является разрешением удалить его из Revit.
