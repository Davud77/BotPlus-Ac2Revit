# Нативные профильные колонны: этап 15 октября 2026

Задача этапа: заменить распознанные IFC-сетки нативными колоннами с изменяемой высотой. Предыдущая модель со всеми 1292 колоннами сохраняется; работа выполняется в новых копиях.

## Изменения

`prepare_extruded_columns.py` распознаёт вертикальные выдавливания по полному телу каждой IFC-части. Проверяются нижняя/верхняя крышки, вертикальность боковых граней, отверстия и объём. Габариты сами по себе не используются как сечение. Геометрия с изменением формы по высоте остаётся DirectShape.

Отобрано 968 кандидатов, включая 579 профильных колонн. Это 89 вариантов семейств и 12 исходных GUID профилей. 663 кандидата состоят из одной части, 305 — из двух. У 310 есть постоянные смещения торцов частей относительно уровней. 46 уже нативных колонн не изменяются.

`ExtrudedColumnReplacer.cs` создаёт отдельные RFA на основе Metric Structural Column. Контуры становятся нативными Extrusion, с отверстиями и несколькими частями. Нижние и верхние грани привязаны к опорным уровням семейства. Для смещённых частей создаются опорные плоскости с постоянным расстоянием до соответствующего уровня. В проекте задаются home story, base/top offset и поворот. Каждая часть имеет отдельный параметр материала `AC2R_Material_N`.

Высота управляется стандартными ограничениями колонны. Проверка первой принятой колонны каждого семейства поднимает верхний offset на 0,5 м, проверяет реальные габариты и изменение объёма, затем откатывает тест и повторно проверяет исходное тело. Сохраняется исходная высота; тестовое изменение не остаётся в модели.

## Порядок безопасной замены

1. Найти ровно один помеченный DirectShape исходного GUID в категории несущих колонн.
2. Создать нативный FamilyInstance; проверить габариты и объём по фактическому IFC-телу.
3. Проверить изменение высоты и восстановление геометрии для этого семейства.
4. Удалить прежнюю сетку в той же транзакции. Если удаляются пользовательские зависимости, транзакция откатывается. Допускаются только сопутствующие внутренние элементы Revit: базовый класс Element, без категории/имени/геометрии/исходного тега и с исключительно read-only параметрами. Они журналируются отдельно. Аннотации, размеры, другие элементы модели, DataStorage и writable данные под это исключение не попадают.
5. Присвоить исходный GUID новой колонне и проверить commit. При любой ошибке прежний DirectShape остаётся.

После замены необходим независимый аудит всего набора: уникальность GUID, количество, габариты, объём и выборочное двунаправленное расстояние между поверхностями нативного тела и IFC-тесселяции. Для оставшихся DirectShape сравнивается полный набор треугольников.

## Ограничения

- Параметрическая высота не означает произвольно параметрическую ширину каждого исходного профиля. Сечение хранится в редактируемом эскизе семейства; следующая задача — осмысленные размерные параметры и типоразмеры.
- Изменение уровня/высоты сохраняет постоянные смещения торцов частей; архитектурная логика новых узлов и соединений с перекрытиями автоматически не пересчитывается.
- Материалы нескольких частей пока не всегда сопоставлены. Доступные параметры материала не являются доказательством полного переноса отделки, текстур и строительных свойств.
- Манифест, RFA, копии RVT и отчёт сохраняются отдельно. Инкрементальное обновление существующих нативных колонн ещё не реализовано.
- На основе этой модели не заявляется универсальная нативная поддержка круглых, наклонных, сужающихся или всех сегментированных колонн.
- В этом этапе верх задан тем же home-story уровнем и offset полной высоты, что сохраняет геометрию и допускает ручное изменение уровня/высоты. Исходный `relativeTopStory` ещё не использован для выбора верхнего этажа: при изменении этажей связь с исходным верхним этажом автоматически не воспроизводится. Это отдельное следующее исправление семантики ограничений.
