## Реализация

Обычная кнопка **Archicad JSON → Импорт JSON** распознаёт `pipeline.json` формата `ac2r.pipeline/1`. Команда «Проверить JSON» проверяет входные файлы и показывает порядок без изменения модели. `PipelineRunner` — общий код для кнопки и контрольных запусков; отдельной реализации для демонстрации нет.

Файл для текущего проекта: `artifacts/pipeline/abakan-20261015/pipeline.json`. Он явно ссылается на исходный JSON, проверенный IFC, манифест осей, тела/планы колонн, тела/планы балок, шаблоны семейств и каталог проёмов. Python используется при подготовке входного пакета; кнопка читает готовые JSON и работает через Revit API. Свежий экспорт другой модели требует подготовки нового пакета, пути текущего проекта не универсальны.

Порядок выполнения:

1. Уровни, материалы, цвета/прозрачность, типы конструкций.
2. Нативные оси IFC Grid; исходные подписи сохраняются в метаданных, недопустимые символы имени Revit заменяются явно.
3. Простые нативные колонны, затем недостающие IFC-тела и распознанные профильные семейства.
4. Стены, перекрытия, Morph.
5. Тела балок, простые нативные балки, затем нативные подрезки сложных балок.
6. Нативные вырезы стен, затем отдельная проверенная геометрия дверных/оконных заполнений.
7. Соединения стен и **повторное создание/оценка помещений только после всех физических этапов**. Допуск площади остаётся 1 м²; замкнутость обязательна.
8. Общий диагностический вид и поэлементные отчёты.

Выполнение не перезаписывает существующие элементы по имени. Наличие исходного GUID проверяется через ExtensibleStorage; уже известные элементы сохраняются. Обновление изменившегося источника/локальных правок не считается решённой синхронизацией. Для пространственной переоценки удаляются только собственные Room/Space; зависимые пользовательские аннотации не удаляются молча.

## Подрезки балок

`CutBeamReplacer` создаёт настоящую CurveDrivenStructural балку с исходным сечением, уровнем, отметками и материалом. Тело IFC превращается в закрытый Solid без salvage. Вычисляется разность «номинальная балка − IFC net body»; каждая связная часть разности становится нативным незакреплённым Void FreeForm в отдельном RFA. `InstanceVoidCutUtils` связывает вычитающее семейство только с исходной балкой.

До удаления прежнего DirectShape проверяются обе Boolean-разности между полученной балкой и IFC-телом. Геометрия вне номинального сечения, незамкнутая сетка, неприемлемые рёбра или неуспешный Boolean сохраняют прежний DirectShape с причиной. Угловые/торцевые подрезки не подменяются одним уменьшенным прямоугольником. Сами вычитающие тела пока фиксированы относительно исходной системы координат: после изменения длины или узла требуется их пересчёт из источника.

Первая контрольная выборка v20: **4/4 сложные балки заменены**, у первых двух 4 и 11 отдельных вычитающих тел. Независимый аудит: в категории 170 элементов, 10 нативных и 160 DirectShape; **10 nativeSurfaceVolumeVerified и 160 meshVerified**, 0 пропусков/лишних GUID. Максимум выборочной разницы поверхности 0,002941 мм. Артефакты: `artifacts/stages/cut-beams-trial-comparison-20261015/comparison.json`.

## Окна, двери и проёмы

Извлечено **1783/1783** IFC-проёма, связанных с исходными Door/Window: 1105 дверных заполнений, 565 окон, 113 пустых проёмов. Для физических заполнений используются точный `IfcDoor/IfcWindow.Tag` и связи FillsVoids/VoidsElements; для пустых — точный GUID стены и единственное совпадение полной геометрии проёма в пределах 1 мм. Исходные библиотечные имена/размеры/флаги хранятся отдельно от фактической net-геометрии.

127 вырезов являются полными прямоугольными призмами; 1656 имеют ступенчатые/иные откосы и требуют полного вычитающего тела. Все исходные сетки вырезов прошли проверку замкнутости. `OpeningStage` создаёт либо нативный Opening, либо семейство с точным Void, затем проверяет реальную стену против «стена до выреза − IFC Void». Нулевое пересечение или отсутствующий нативный хост не исправляются угадыванием положения.

Геометрия заполнений пока создаётся как DirectShape соответствующей категории Door/Window после успешного выреза. Это сохраняет реальные рамы, полотна, стекло и сложную форму; **не является полноценным wall-hosted семейством двери/окна с параметрами GDL, аналитикой открывания и автоматической реакцией на редактирование стены**. Связь с хостом обеспечивается отдельным нативным вырезом и исходным GUID. Следующая стадия параметрики — калиброванные семейства заполнений.

Ниже — история проб.

- Контроль v20 создал **61/61 нативную ось**.
- Вырезы первых четырёх контрольных элементов прошли проверку, но запись/чтение файла заполнений остановилась из-за незакрытого FileStream. Поток исправлен в v21; следующая проба включает окно.
- На момент ранних проб полный импорт ещё проверялся; актуальный завершённый результат приведён выше. Итоговая приёмка всех узлов и всех геометрических тел ещё необходима.
- В полном запуске с нуля созданы все 1292 колонны (990 нативных), 61 ось и ресурсы. Во время стен перезапустился Windows-сеанс: WMI LastBootUpTime 15.10.2026 12:46:30 +03:00, Revit завершился без финального отчёта. Это зафиксировано как interrupted, не как успешный импорт. Сохранённый этап колонн — `artifacts/stages/complete-pipeline-all-20261015-093754/Abakan_complete.rvt`.
- В v23 добавлены пакеты по 200 стен/перекрытий с сохранением RVT и checkpoint-отчёта, промежуточные сохранения балок и проёмов. Продолжение — `artifacts/stages/complete-pipeline-all-20261015-095421/Abakan_complete.rvt`; повторного создания уже известных GUID нет.
- Для точного 1-мм ребра сложного проёма добавлен BRepBuilder.SetAllowShortEdges без удаления граней, упрощения или утолщения. После построения проверяется объём; неуспешное построение остаётся явной ошибкой.

Геометрия нативных тел сравнивается с IFC-тесселяцией; выборочная проверка поверхности не доказывает формальное равенство аналитического BRep. Нативные вычитающие тела проверяются дополнительно Boolean-разностями. Цвета материалов не равны appearance-текстурам; изображения и surface overrides ещё требуют отдельного этапа.
