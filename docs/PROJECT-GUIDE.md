Этот документ — карта репозитория и рабочих данных. Пользовательский запуск описан в [инструкции интерфейса](REVIT-EXCHANGE-INTERFACE.md), установка — в [INSTALL.md](../INSTALL.md), задачи разработки — в [ROADMAP.md](ROADMAP.md).

## Исходный код

| Каталог | Назначение |
|---|---|
| `revit/Ac2Revit` | C#-надстройка Revit: интерфейс, адаптеры, этапы сборки, контрольные точки и отчёты |
| `revit/assets` | Семейства и шаблоны, необходимые для сборки пакета |
| `exporter/ac2r` | Чтение Archicad через API/Tapir, архивирование и нормализация JSON |
| `tools` | Подготовка IFC-геометрии, сопоставления и диагностические CLI с явными входными файлами |
| `contracts` | Версионируемые JSON-контракты |
| `config` | Настройки обмена, правила штриховок и примеры конфигураций |
| `tests` | Автоматические проверки и C#-проверка контракта |

## Локальные рабочие данные

`artifacts/sessions/<сеанс>/source` содержит JSON, IFC и архивы ответов API. План `pipeline.json` связывает этапы конкретного сеанса; рядом сохраняются подготовленные тела, RVT и отчёты. Для проверки результата используются `pipeline-report.json`, `source-coverage.json`, отчёты геометрии, помещений и материалов.

`artifacts`, `dist`, исходные BIM-файлы, дампы и локальные среды исключены из Git. Архивы `source/raw` входят в полный экспорт, если JSON ссылается на них через `gdlReference`; удалять их как временные файлы нельзя. Набор данных одного сеанса не подменяется файлами другого.

Необязательный `config/project-registry.local.json` сохраняет соответствие пути PLN и стабильного `projectId`, например при перемещении файла. Формат задан в [примере](../config/project-registry.example.json). Реестр локальный и не включён в Git; без записи идентификатор детерминированно вычисляется по пути сохранённого PLN.

Исторические отчёты в [history](history/README.md) отделены от текущих инструкций. Полные исходные доказательства и разовые рабочие скрипты хранятся в локальном архиве; они не являются зависимостями универсальной сборки.
