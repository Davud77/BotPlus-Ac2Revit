Добавлены проверяемое преобразование IFC в систему координат API, дополнительные тела IFC и контрольные точки памяти. Пакетный расчёт помещений v45 пока требует полного натурного прохода. # Перенос из интерфейса Revit — версия 41

Плагин установлен для Revit 2026. Вкладка **Archicad → Revit** содержит семь кнопок с векторными значками 16/32 px.

| Кнопка | Действие |
|---|---|
| Archicad → Revit | Прочитать открытый Archicad, выгрузить JSON и IFC, подготовить этапы и собрать модель |
| Экспорт Archicad | Выполнить чтение и подготовку без построения в Revit |
| Продолжить сеанс | Восстановить завершённое чтение JSON из архива и продолжить сборку. Готовый IFC используется повторно; отсутствующий экспортируется после сверки исходной модели |
| Собрать экспорт | Собрать последний завершённый сеанс в новом или текущем проекте |
| Проверить JSON | Выбрать manifest.json или pipeline.json и проверить входные данные/порядок |
| Импорт JSON | Импортировать выбранный подготовленный файл в текущий проект |
| Папка обмена | Открыть artifacts/sessions с исходными данными, моделями и отчётами |

## Обычный запуск

1. Открыть сохранённый PLN в Archicad с Tapir 1.7.0. Дождаться загрузки и закрыть диалоги открытия.
2. Открыть Revit 2026. На главной странице нажать переключатель рабочего пространства в левом верхнем углу, чтобы появилась лента. Создавать пустой проект заранее необязательно.
3. Выбрать **Archicad → Revit → Archicad → Revit**.
4. Проверить отображаемый PLN, порт и IFC-транслятор. Для Абакана ранее использовался «Точный Экспорт Геометрии»; у других PLN список собственный. Транслятор должен сохранять геометрию и исходные координаты.
5. Оставить «Собрать в новом проекте Revit» или явно выбрать текущий проект. При необходимости выбрать RTE. Шаблон определяет доступные образцы штриховок.
6. Нажать **Экспортировать и собрать**. До окончания чтения не редактировать исходный Archicad.

Порт по умолчанию 19723. Если Archicad работает на другом порту, ввести его и нажать «Подключиться». Запросы направляются только на 127.0.0.1. Команды Tapir обёрнуты в API.ExecuteAddOnCommand / TapirCommand.

## Что выполняется

Экспорт читает этажи, инвентаризацию, подробности элементов, привязки/отношения стен, IFC-идентификаторы, конструкции, материалы, покрытия, профили, штриховки, перья и классификации. Затем Archicad экспортирует EntireProject в IFC выбранным переводчиком. Исходные PLN не сохраняются плагином.

Из свежих JSON/IFC готовятся оси, проверенные простые колонны, точные тела колонн/стен/балок, профили колонн, прямоугольные балки, окна/двери и их проёмы. Отдельно читаются явные roomSeparator=true и сохраняются точные исходные кривые. Сопоставление использует GUID в Tag либо явный IFC ID, полученный из Archicad; имена и близость элементов для идентичности не используются.

Сборка: ресурсы и сопоставление штриховок → оси → простые колонны → тела/профили колонн → стены и перекрытия → дополнение стен → балки и нативные подрезки → проёмы и заполнения → разделители → сопряжения стен и помещения → планы/3D и контрольные отчёты. Допуск помещений **1 м²** сохранён.

Штриховки подбираются по явным правилам config/hatch-analogues.ru.json среди реальных Drafting-образцов текущего шаблона. Отсутствующий аналог попадает в CSV как unmapped. Рисунок не заменяется произвольной сплошной заливкой.

## Объём экспорта и остановка

Пользовательские свойства и все GDL-параметры включаются отдельными флажками. Геометрические размеры окон/дверей и IFC-тела доступны без полной выгрузки GDL. На полном Ипподроме исходные ответы заняли 4,78 ГБ. В v41 большие GDL-массивы хранятся в source/raw, а элементы содержат gdlReference: путь относительно папки source, JSON Pointer, размер файла и SHA-256. Полные значения сохранены. Копировать экспорт нужно вместе с source/raw. JSON записывается потоком; контрольные суммы файлов также вычисляются потоком. Опция GDL по умолчанию выключена и для построения геометрии не обязательна.

Во время экспорта отображаются журнал и кнопка «Остановить». Останавливается локальный обработчик; уже отправленная операция Archicad может завершиться отдельно. Сеанс получает статус cancelled и не считается готовым для сборки. Указатель last-completed.json публикуется только после успешной подготовки всех файлов. Незавершённый экспорт не подменяет предыдущий.

## Файлы и ограничения

Каждый запуск хранится в отдельной папке artifacts/sessions/ИмяПроекта-время. Там находятся source/manifest.json, snapshot.json, model.ifc, архивы ответов API, pipeline.json, планы этапов и session.json. Сборка создаёт model-время.rvt; отчёт находится в revit-run-время/pipeline-report.json. source-coverage.json показывает наличие каждого исходного GUID в Revit по категориям.

Наличие кнопки полного запуска не означает стопроцентную нативность всех элементов: крыши, лестницы, ограждения, объекты и другие категории без адаптера сохраняются в JSON, а отсутствие в модели показывается в отчёте. Сложные поддержанные элементы могут передаваться как DirectShape. Такие стены отмечаются «НЕПОЛНОЦЕННАЯ СТЕНА». Текстуры изображений и UV-развёртка пока не переносятся. Конструктивное поведение профилей новых проектов не объявляется бетонным без проверенного соответствия исходных материалов.

Это локальная установка: папка проекта содержит самостоятельный базовый CPython в runtime/python (40,2 МБ), среду библиотек .ifc-env, exporter, tools и config. Зависимость от кэша Codex устранена; для запуска достаточно Revit и Archicad. Проверены локальные IfcOpenShell 0.8.5, NumPy 2.5.4, Shapely 2.2.0 и SSL. Четыре необходимых RFA/RFT упакованы рядом с DLL в dist/Revit2026-v41/assets. Для переноса на другой компьютер нужен отдельный установщик с этими зависимостями и перенастройкой путей среды.

В сборку добавлена защита снимка: новый сеанс для уже импортированного проекта не должен незаметно смешиваться с другим JSON/IFC. Повторная сборка того же сеанса допустима; изменённую исходную модель следует собирать в новом проекте, пока адаптер обновления геометрии не реализован.

Расширенная таблица содержит 52 явных правила. На каталогах Ипподрома доступны аналоги для 95/95 определений материалов, Турали — 96/96, Абакана — 787/865. Это проверка доступности правил против записанного набора образцов, а не подтверждение их назначения в новой модели; фактическое соответствие проверяется отдельно после импорта.

## Проверка разработки

Сборка C#: 0 ошибок, 0 предупреждений. Python: 82 теста, включая конфликт IFC ID/Tag, отсутствие аналога в другом шаблоне, смену активного проекта и отказ IFC без публикации неполного сеанса. Контракт свежего Ипподрома: 15 уровней, 41 тип, 32 623 элемента; GUID и зависимости проверены в C#.

Проверено в интерфейсе: вкладка и все значки, открытие мастера без проекта Revit, подключение к Ипподрому, чтение проекта, остановка и исключение отменённого сеанса из сборки. Полная проверка нового сеанса продолжается; окончательный результат фиксируется отдельно после завершения.


## Исправление ошибки экспорта Ипподрома — v41

Сбой 17.10.2026: MemoryError при финальной сериализации snapshot.json после чтения GDL для 18 188 элементов. Полный разбор и проверка восстановления: [отчёт](IPPODROM-EXPORT-2026-10-18.md). Исправлены запись JSON, вычисление хешей, накопление GDL и кэш ответов. Пустое сообщение «ОШИБКА:» заменено понятным текстом с типом и этапом в session.json.

Для неудачного сеанса нажмите «Продолжить сеанс» и выберите artifacts/sessions/ЖК Ипподром-РАБОЧКА-20261017-113428695/session.json. Перед созданием отсутствующего IFC сверяются состав и геометрические подробности всех экспортируемых категорий. При изменении исходника продолжение отклоняется: требуется новый экспорт. Существующий повреждённый IFC не перезаписывается автоматически.
