# Опорные линии, соединения стен и площади помещений

## Что задаёт положение стены в Archicad

Прямая стена задаётся направленной опорной линией `begCoordinate → endCoordinate`, положением этой линии в конструкции, ориентацией `flipped`, боковым `offset`, конструкцией и отметкой относительно этажа. Порядок концов линии и flip важны: они определяют наружную сторону и направление раскладки слоёв.

Обычная стена имеет три положения опорной линии. Многослойная — шесть, включая границы и центр сердцевины. Наружная сторона соответствует первому слою конструкции. Положительный offset от наружной/внутренней поверхности перемещает опорную линию к центру конструкции; при изменении настройки само тело смещается относительно неподвижной линии.

Источники: [Archicad 28 — Reference Line](https://help.graphisoft.com/AC/28/INT/_AC28_Help/040_ElementsVB/040_ElementsVB-7.htm), [API_WallRelation](https://archicadapi.graphisoft.com/documentation/api_wallrelation?mkto_referrer=direct).

## Поля JSON и соответствие Revit

В исходном `raw.details` эти поля уже сохранялись. Нормализованный payload теперь содержит `referenceLine`, `referenceOffset`, `flipped`, `curve`, `bottomOffset`, `height`, `typeKey`.

| Archicad | Revit |
|---|---|
| Outside | FinishFaceExterior — чистовая поверхность снаружи |
| Center | WallCenterline — осевая линия стены |
| Inside | FinishFaceInterior — чистовая поверхность внутри |
| CoreOutside | CoreExterior — наружная граница сердцевины |
| CoreCenter | CoreCenterline — осевая линия сердцевины |
| CoreInside | CoreInterior — внутренняя граница сердцевины |

В данном PLN: Outside — 180, Center — 598, Inside — 336, CoreOutside — 184, CoreCenter — 5 631, CoreInside — 60 стен. Ненулевой offset имеется у 175 прямых стен: 30 Outside, 102 Inside, 27 CoreOutside, 16 CoreInside.

В Revit выбранная стандартная линия относится к геометрической плоскости поверхности/сердцевины. Для ненулевого Archicad offset координаты этой плоскости надо пересчитать. Для прямой стены:

```text
nativeCentreCurve = sourceReferenceCurve + outwardNormal × (signedOffset − revitKeyLineOffset)
signedOffset = +offset для Outside/CoreOutside
signedOffset = −offset для Inside/CoreInside
revitKeyLineOffset = CompoundStructure.GetOffsetForLocationLine(...)
```

`outwardNormal` берётся из фактической Wall.Orientation после применения flip. `LocationCurve` задаёт геометрическую ось тела, поэтому одного присваивания WALL_KEY_REF_PARAM недостаточно: надо вычесть смещение выбранной поверхности/оси сердцевины от геометрического центра. Исходные координаты опорной линии остаются в JSON; они не заменяются преобразованными.

Формула проверена на десяти стенах по реальным bounding boxes Archicad: zero/nonzero offset, оба flip, пять вариантов положения линии. Для этих осевых прямых стен normal-range поверхностей совпал с расчётом в пределах 0,001 мм. Проверка AABB не является полноценным сравнением всего BRep после соединений/SEO. Арки с ненулевым offset требуют отдельной радиальной проверки и пока не допускаются.

Данные проверки: `artifacts/reference-face-probe/source-boxes.json` и `calibration.json`. Версия v5 записывает реальные bbox контрольных прямых стен в `Report.WallOffsets` до соединения. Нативный тест `offset-fixture/import-v2-20261013-130609.calibration.json` подтвердил 8 из 8 созданных контрольных стен, максимальное отклонение AABB — 1,421 × 10⁻¹⁴ м. Две исходные контрольные стены не созданы из-за конструкции без core; они не включены в число проверенных нативных стен.

## Почему стены раньше не соединялись

Импортёр явно вызывал `DisallowWallJoinAtEnd` для обоих концов каждой стены, чтобы Revit не изменял геометрию во время размещения. Само по себе это не ошибочно как промежуточный этап, но последующий этап соединений отсутствовал. На присланных скриншотах видны неочищенные торцы и пересечения.

Теперь сначала создаются все стены, затем отдельная транзакция соединяет их перед вычислением помещений:

1. Из Archicad GetRelationsOfElements получены 21 638 направленных связей для 6 989 стен. Это связи концов, Т-примыканий к опорной линии и пересечений; их нельзя включать в граф порядка создания, поскольку он циклический.
2. Сопоставление по source GUID связывает только реально созданные нативные стены. В проверке участвуют интервалы высоты: стены разных этажей, лишь касающиеся по Z, не соединяются.
3. `conBeg/conEnd` разрешают соответствующие концы; `conRef/con` обрабатываются как Т-примыкания. Для `conX` выполняется отдельная попытка JoinGeometry после создания концовых соединений. Опорная линия Archicad используется отдельно от смещённой геометрической оси Revit.
4. Перекрывающиеся коллинеарные опорные линии не объединяются автоматически: это неоднозначная геометрия, требующая отдельного разбора.
5. Если исходная топология прочитана, пустой список связей означает отсутствие соединений. Геометрическая догадка не подменяет этот список.
6. Для данных без топологии допускается только точное примыкание конца к ограниченной опорной кривой в пределах 1 мм. Пересечения двух внутренних участков по одной лишь близости не объединяются.
7. После автоматического разрешения концов проверяются реальные соседи Revit. Предложенные соседи, которых нет в исходной топологии, отклоняются. Native-проверки записываются в `Report.WallJoins`; разрешение конца не объявляется подтверждённым соединением, пока не найден native-сосед.

На полной модели единая транзакция не выдержала часть несовместимых узлов и откатилась. Обработка изменена: пакеты по 64 конца, при ошибке пакет рекурсивно делится до отдельного конца. Успешные пакеты сохраняются. Булевы соединения пересечений имеют собственные транзакции, поэтому ошибка одного узла не отменяет весь результат.

Проверки native-соседей фиксируются после каждого пакета. Последующие пакеты могут изменить граф соединений; эти записи не являются отдельным финальным аудитом всех соседей после завершения импорта.

Минимальный интеграционный тест в Revit подтвердил угловые и Т-соединения; стена выше на отдельном этаже исключена из плана. В этом тесте разрешены 17 концов, у 9 прочитаны native-соседи. Площади двух закрытых квадратов рассчитались корректно.

Совпадение топологии не гарантирует идентичного разрешения всех слоёв: приоритеты материалов Archicad и алгоритмы соединений Revit различаются. Окончательная проверка проводится по результату Revit и площадям, а не только по успешному вызову API.

## Допуск площади 1 м²

Проверка теперь использует абсолютное условие:

```text
abs(revitAreaM2 − sourceAreaM2) ≤ roomAreaToleranceSquareMeters
roomAreaToleranceSquareMeters = 1.0
```

Обе площади сохраняются без подгонки. Незамкнутое помещение с площадью 0 не принимается даже при попадании в допуск. Отчёт содержит разницу, предел и решение по каждому помещению.

В предыдущем результате у 486 отклонённых помещений разница была 0,016825–77,2251742 м², медиана 4,8899195 м². Из них 207 попадали в 1 м², 279 — нет. Таким образом, при прежней геометрии допуск мог бы дать 209 принятых помещений с учётом двух уже принятых. После изменения соединений это только baseline, а не прогноз окончательного числа.

CSV всех 486 отклонений: `artifacts/runtime/room-area-analysis/differences.csv`. Минимальный тест в Revit принял разницу 0,49 м² и отклонил 1,47 м².
