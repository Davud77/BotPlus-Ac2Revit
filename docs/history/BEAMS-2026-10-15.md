# Балки и ригели: 15 октября 2026

Исходное состояние: в JSON 170 элементов `Beam`, в открытой модели с 1292 колоннами категория `OST_StructuralFraming` была пустой. Прежний полный импорт блокировал балки без явного сопоставления семейств. Наличие исходной записи не означало её создания.

## Исходные данные и идентичность

- В IFC найдено 170 `IfcBeam`. Для каждого из 170 исходных Beam есть ровно один объект с `IfcBeam.Tag = sourceGuid`; пространственный поиск вместо GUID не применяется.
- Все имеют привязку `TopCenter`, offset 0 и прямую ось в плане. Одна балка наклонная; её высоты нельзя приравнивать к одной отметке Z.
- 160 сечений шириной 0,4 м, 8 — 0,6 м, 2 — 0,8 м. В исходных данных нет сложных profileId или явных отверстий, но фактические тела содержат результаты подрезок/соединений.
- Отдельной исходной категории «Ригель» в этой выгрузке нет: рассматриваются реальные элементы Archicad Beam. Поиск названия не доказывает полноту произвольных GDL-объектов других моделей.
- Извлечено 170 тел и 11045 треугольников. У 159 сеток каждое ребро принадлежит двум треугольникам; у 11 проверка замкнутости не прошла. Это ограничение полученной тесселяции, не доказательство дефекта исходного BRep. Автоматическое зашивание не выполняется.

## Нативные балки: область адаптера

`prepare_native_beams.py` допускает замену только если полное закрытое IFC-тело доказуемо является номинальным прямоугольным брусом: совпадают обе крышки, боковые поверхности, сечение, объём и положение относительно TopCenter. Проходят **6** элементов. 152 имеют промежуточные вершины вдоль оси и не проходят проверку постоянного выдавливания, 11 не проходят замкнутость сетки, 1 требует адаптера наклонных балок.

`RectangularBeamReplacer.cs` использует отдельную копию штатного бетонного семейства `AC2R_RectangularBeam.rfa`, правильную категорию и `CurveDrivenStructural`. Задаются ширина/высота типа, опорный уровень, верхняя привязка, центр по Y и исходный строительный материал. Ось берётся из мировых координат JSON; автоматически подрезать торцы Revit не разрешается. До удаления сетки проверяются реальная ось, тело и объём. Для нового типа фактическая длина увеличивается на 0,5 м, проверяется изменение тела/объёма, затем тест откатывается.

Первые пробы откатывали все шесть замен: сначала недоступен параметр отметки конца, затем обнаружена неверная проверка опорного уровня. В этой конфигурации `NewFamilyInstance` выбирал ближайший reference level, а `Element.LevelId` оставался `InvalidElementId`. Рабочая v19 явно задаёт `INSTANCE_REFERENCE_LEVEL_PARAM`, восстанавливает мировую `LocationCurve` и проверяет reference level, ось и тело. Эти проверки нельзя заменять чтением одного `LevelId`.

## Воспроизведение этапа

Использовать `.ifc-env/Scripts/python.exe`. Сборка add-in должна быть загружена в Revit; обработчик выполняет локальную очередь через ExternalEvent. Каждый запуск создаёт новый RVT. Команды постановки заданий выполнять последовательно, дожидаясь `result.json`.

```powershell
.\.ifc-env\Scripts\python.exe tools\prepare_column_bodies.py --kind Beam --out artifacts\stages\beam-reference-NEW
.\.ifc-env\Scripts\python.exe tools\queue_beam_stage.py --source ПУТЬ_К_ПРОВЕРЕННОЙ_МОДЕЛИ.rvt --reference artifacts\stages\beam-reference-NEW\beam-bodies.json --limit 3
# После успешной контрольной пробы: новый запуск от той же исходной модели без --limit.
.\.ifc-env\Scripts\python.exe tools\prepare_native_beams.py artifacts\stages\beam-reference-NEW\beam-bodies.json --out artifacts\stages\beam-native-plan-NEW
.\.ifc-env\Scripts\python.exe tools\queue_native_beams.py --source ПУТЬ_К_МОДЕЛИ_СО_170_БАЛКАМИ.rvt --plan artifacts\stages\beam-native-plan-NEW\native-beams.json
.\.ifc-env\Scripts\python.exe tools\queue_geometry_audit.py ПУТЬ_К_РЕЗУЛЬТАТУ.rvt --name beams-check --category beams
.\.ifc-env\Scripts\python.exe tools\compare_column_geometry.py artifacts\stages\beam-reference-NEW\beam-bodies.json ПУТЬ_К_АУДИТУ\beams.jsonl --kind Beam --out artifacts\stages\beam-comparison-NEW
```

## Что ещё требуется

Этапы геометрии и нативной замены сейчас запускаются отдельными заданиями; обычная кнопка импорта JSON по-прежнему использует прежний mapping для Beam. Нужно объединить оркестрацию в пользовательский сценарий после приёмки адаптеров.

Для оставшихся тел нужны нативные подрезки/вырезы и отдельный адаптер наклона с контролем торцов, затем соединения с колоннами/стенами по исходным связям. Нельзя включать автоматические соединения и принимать изменившуюся геометрию без сверки. У DirectShape нет полноценной параметрики, нативных узлов и аналитической модели. Материал геометрических тел, surface overrides и текстуры ещё не назначены; у нативной пробы проверяется строительный материал. Категории осей, дверей и окон этим этапом не закрываются.
