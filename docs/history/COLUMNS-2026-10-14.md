## Как это работает

1. JSON задаёт project ID, source GUID, этаж, исходное сечение, anchor, координаты, высоту, поворот и профиль.
2. Из IFC выбирается строго один IfcColumn с точным `Tag` = GUID Archicad. Сопоставления по ближайшему положению нет.
3. Читаются Body-представления. Если у родительской колонны нет собственного Body, обходятся все дочерние части. Если собственный Body есть, дочерние тела повторно не добавляются. Это устранило пропуски составной геометрии.
4. Для простых колонн предварительно проверяется, что фактический IFC net body совпадает с номинальным прямоугольным телом: положение, шесть граничных плоскостей, замкнутость и объём. Из 686 непрофильных колонн только 46 прошли эту строгую проверку. Другие имеют отличия фактического тела и не подменяются прямоугольником.
5. Для принятых 46 загружается изолированная копия стандартного прямоугольного семейства; создаются типы по сечению, назначаются исходный материал, уровни/offset и поворот. Созданное тело семейства снова сверяется с IFC. Эти элементы — нативные несущие колонны.
6. Для остальных 1246 строится DirectShape из всех треугольников фактической IFC-геометрии в категории несущих колонн. Сохраняются исходный GUID, марка, reference IFC ID и исходные параметры. Один GUID соответствует одному элементу, даже если внутри несколько геометрических частей.
7. Revit может немного изменить численные координаты Mesh. Проверяются соответствия исходных вершин в пределах 1 мм, затем полный набор треугольников с учётом их кратности. Если изменилось количество или связность граней, элемент откатывается. Исходные координаты при этом не округляются и не сдвигаются.
8. Отдельное чтение геометрии из конечного документа проверяет созданные элементы повторно, независимо от отчёта о создании.

## Исправленные ошибки

- `GetGeometricalObjects()` у результата TessellatedShapeBuilder вызывается только один раз. Повторный вызов, присутствовавший в старом IFC-адаптере, давал исключение без сообщения и блокировал все тестовые элементы.
- Полная диагностика исключений теперь содержит этап и тип ошибки, а не только потенциально пустой `Exception.Message`.
- Задания обрабатываются через ExternalEvent: переключение между уже открытыми документами из Idling запрещалось Revit.
- Проверка Mesh теперь допускает измеряемую численную погрешность Revit и одновременно проверяет грань целиком; грубое сравнение округлённых координат на границе ячеек давало ложные отказы.
- Метка задания `completeWithErrors` отличает завершение обработчика с блокировками от успешного создания всех элементов.

## Что ещё нужно для полноценного переноса колонн

1. **1246 геометрических элементов не являются параметрическими FamilyInstance.** У них нельзя штатно менять ширину/профиль/высоту как у семейства несущей колонны. Следующий этап — извлечение профиля и материалов частей, генерация параметрических семейств, собственные адаптеры отсечений, отделки и составных колонн.
2. У 1291 исходной IFC-колонны все части прошли проверку замкнутости по рёбрам; у GUID `161D07C5-78CC-4760-BE3B-E94AC20C3A3A` одна часть не прошла. Она перенесена как исходная сетка и прошла сравнение треугольников, но замкнутый solid/объём для неё не заявляется. Исходная геометрия не «лечилась» догадками.
3. Слои, материалы отдельных IFC-частей и 3D-поверхности сложных колонн ещё требуют назначения. У нативных 46 исходный строительный материал назначен; RGB/прозрачность 865 материалов также перенесены, но изображения текстур и appearance assets пока отсутствуют.
4. Все 1292 исходных элемента имеют `isSlanted=false` и `circleBased=false`. Проверка покрывает все колонны **этой модели**, включая её 14 сложных профилей. Для универсального переноса наклонных, круглых, конических и сегментированных колонн нужны дополнительные исходные/контрольные примеры; универсальная поддержка нативных типов не заявляется.
5. Revit выдал предупреждения о повторяющейся марке. Марки сохраняются из Archicad; уникальность идентификации обеспечивает GUID. Блокирующих Revit-ошибок в итоговом геометрическом этапе нет.
6. Площади существующих помещений после добавления колонн ещё не приняты повторно. Счётчики помещений предыдущего этапа нельзя считать повторной проверкой новых ограждений.
7. Инкрементальное изменение/удаление колонн не реализовано. Строгая проверка запрещает дублировать GUID, который уже представлен в документе.

## Воспроизведение

```powershell
# Исходные IFC и JSON уже лежат в рабочей папке. Выходные папки должны быть новыми.
.ifc-env/Scripts/python.exe tools/prepare_stage_plan.py --out artifacts/stages/new-preflight
.ifc-env/Scripts/python.exe tools/prepare_column_bodies.py --out artifacts/stages/new-bodies

# Текущий диагностический runner использует зафиксированные проверенные входные папки.
.ifc-env/Scripts/python.exe tools/queue_column_stage.py native
# После завершения native, указать его RVT и отчёт, чтобы не создавать колонны повторно:
.ifc-env/Scripts/python.exe tools/queue_column_stage.py body --source PATH_TO_NATIVE_RVT --exclude-native-report PATH_TO_NATIVE_REPORT

.ifc-env/Scripts/python.exe tools/queue_geometry_audit.py PATH_TO_FINAL_RVT --name columns-audit --category columns
.ifc-env/Scripts/python.exe tools/compare_column_geometry.py PATH_TO_COLUMN_BODIES PATH_TO_COLUMNS_JSONL --out NEW_COMPARISON_FOLDER
```

Сборка v11 должна быть загружена в Revit. Каждый runner создаёт отдельную копию; при наличии другого ожидающего задания новая очередь не записывается.

Проверки кода: 22 Python-теста прошли; C# сборка v11 — без ошибок и предупреждений. Контракт контрольного манифеста проверен C#-валидатором, повторяющийся GUID отклонён.
